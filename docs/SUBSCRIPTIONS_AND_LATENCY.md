# Подписки, Авто и задержка

Netch читает ссылки серверов, Base64-списки и JSON-конфигурации Xray. Один объект
Xray отображается как один профиль. Сохраняются его outbounds, маршрутизация,
балансировщики и observatory, включая XHTTP и цепочки внутри профиля.
Локальные входы заменяются SOCKS-входом Netch; внешний API и пути журналов из подписки не запускаются.

Профиль с балансировщиком отмечается «Авто». Стратегия `leastPing` выбирает выход
по наблюдаемой задержке, `leastLoad` — по устойчивости. Правила задаёт поставщик.
См. [маршрутизацию Xray](https://xtls.github.io/en/config/routing.html) и
[observatory](https://xtls.github.io/en/config/observatory.html).

После обновления с версии, которая разбивала такие профили на отдельные серверы,
один раз обновите подписку. Настройки приложения сохраняются.

## Проверка задержки

По умолчанию используется HTTP через VPN. Для каждого профиля запускается отдельный
Xray с временным SOCKS-портом на loopback. Измеряется время HTTP-ответа от адреса
в «Настройки → Подключение → Адрес для проверки задержки». Драйверы и системные
маршруты при такой проверке не меняются. Временный процесс и конфигурация удаляются
после проверки. Одновременно проверяются до четырёх профилей; результаты приходят по мере готовности.

TCP и ICMP доступны для проверки самого адреса. Они не доказывают, что VPN-сервер
пропускает трафик; другой установленный VPN также может влиять на путь пакетов.
Отказ или тайм-аут отображается прочерком, а не значением задержки.

## User-Agent

Это произвольный HTTP-заголовок, а не выбор ядра приложения. По умолчанию подписка
запрашивается с `v2ray`. В поле предложены `v2ray`, `v2rayNG`, `v2rayN`, `Happ` и
`Netch`; своё значение также разрешено. Полного универсального списка нет —
поведение определяет поставщик. Формат Clash/mihomo YAML пока не поддерживается.

## Поставка ядра

Используется официальный Xray v26.3.27; `vendor/xray/build.ps1` проверяет SHA-256
архива. Сборка включает `xray.exe`, `geoip.dat`, `geosite.dat` и лицензию.
Старый `v2ray-sn.exe` не является заменой отсутствующему Xray.

Redirector освобождает Winsock только после собственного успешного WSAStartup.
Это соответствует [контракту Microsoft](https://learn.microsoft.com/en-us/windows/win32/api/winsock/nf-winsock-wsastartup)
и предотвращает повреждение сокетов .NET при очистке не запущенного контроллера.
